핵심 실행 흐름
1. MallangPage의 Pointer/키보드 핸들러가 화면 좌표를 200단위 재질 좌표로 바꾼다.
   실제 입력 좌표를 지연시키지 않는다. 몸이 움직이는 프레임에는 새 몸 중심으로 다시 환산한다.
   바깥 당김의 접촉은 막의 가장자리로 투영하고, 당김 끝과 힘은 실제 포인터에서 계산한다.
2. mallangMaterial의 touch/move가 위치별 체류 시간과 떠난 시각·깊이를 기록한다.
   이동 거리가 3단위 미만이면 머리 표본만 갱신하고, 긴 이동은 공간 표본으로 연결한다.
   새 위치의 체류 시간은 이동 거리에 따라 줄어든다. 정지하면 새 경로 점을 쌓지 않는다.
3. 같은 높이 격자에서 국소 함몰, 주변 융기, 액체 쏠림, 복원과 파동을 계산한다.
   속도가 빠르다고 막의 강성을 높이는 항은 없다. 지연은 내용물 쏠림·복원에만 둔다.
4. mallangMotion이 실제 포인터와 현재 몸 위치에서 장력을 계산한다.
   시뮬레이션의 작은 스텝마다 같은 포인터를 읽는다. 처음 잡기·재잡기 전용 힘 증가 구간은 없다.
   손을 놓을 때 이미 적분된 속도를 보존하며, 별도 발사 충격량을 넣지 않는다.
5. mallangSurface가 같은 높이의 기울기로 조명을 그린다. 외곽과 당김 목·끝은 하나의 경로다.
   얼굴은 같은 필드를 제한된 이동·비율로 읽어 눈·입의 접힘을 막는다.
   윗왼쪽 광원을 말랑이·왁스에 공통 적용한다.
6. 왁스가 덮인 격자는 내용물의 함몰과 융기를 제한한다. 조각이 분할되거나 제거되면
   그 지지력이 줄어든다. 내용물의 실제 함몰과 접촉 깊이가 다시 껍질의 응력에 영향을 준다.
   껍질 위 음영도 같은 격자에서 나오고, 깨진 조각은 그 높이에 맞춰 약하게 움직인다.
7. press/stretch/refill/retract/wall 및 실제 왁스 파괴 상태의 전이에서 소리를 발생시킨다.
   포인터 이동 이벤트마다 소리를 재생하지 않는다.

보존 근사의 정확한 의미
- 기준 원판 위 높이 변화의 가중 적분을 0으로 투영한다.
- 음의 높이 적분(함몰량)과 양의 높이 적분(융기량)이 같은 크기가 되도록 한다.
- 격자의 높이·속도·목표 모두 같은 규칙을 사용하므로 오래 눌러도 내용물이 누적되지 않는다.
- 이 값은 시각적인 높이 재배치 근사다. 3D 부피 보존이나 전체 실루엣 면적 보존이 아니다.
- 당김 목의 3D 단면, 실제 점성 유체 방정식, 껍질의 3D 응력 해석은 구현하지 않았다.

설계 선택
- 일반 C#의 계산 객체를 분리하는 것처럼, 여기서는 순수 JS 재질 모델을 React와 분리했다.
- 페이지의 한 RAF가 입력 상태·몸·표면을 갱신하므로 서로 다른 애니메이션 시계가 어긋나지 않는다.
- React는 모드·조각 위상·음량 같은 UI 상태에만 사용한다. 매 프레임 React 상태를 바꾸지 않는다.
- 말랑이 전용 PNG 인코딩·SVG displacement·foreignObject를 제거했다.
  재사용하는 높이/속도/목표 배열과 조명 픽셀 버퍼를 사용한다.
- 외곽은 96점의 작은 배열과 경로 문자열을 만든다. 모든 할당을 없앴다고 주장하지 않는다.
- 일반 버튼은 기존 SVG 함몰·경로 효과를 유지하며 강도만 3으로 낮췄다.
  버튼의 기존 이미지 인코딩 경로는 남아 있다. 화면 이동용 인위적180ms 대기는 제거했다.
- 한 페이지에서 진행 중인 RAF는 하나이고, 정착하면 멈춘다. 파동·경로·음원에는 한도가 있다.
- 진짜 3D 유체/외부 엔진/새 프레임워크는 요구 규모와 맞지 않아 사용하지 않았다.

발견해서 수정한 사항과 이력 해석
- StrictMode 정리 시 null 화면 참조 접근 → 정리/관찰 콜백의 생명주기 가드.
- 정상 정착 때 target-height 차이가 남아 RAF가 끝나지 않음 → 속도로 정착 판정.
- 목과 끝의 결합에서 외곽 변화가 급해짐 → 연속된 방사형 막 경로로 교체.
- 새 위치가 전체 누름 시간을 물려받음 → 위치별 체류/거리 기반 이력.
- 낮은 프레임에서 체류 시간이 느리게 감 → 실제 시간과 제한된 물리 시간을 분리.
- 긴 프레임 중 장력이 이전 프레임의 한도 위치를 읽음 → 작은 스텝마다 실제 포인터를 참조.
- 외곽 융기의 벽 침범 가능성 → 최대104단위 한도와 일치하는 방 여유 확보.
- 큰 조각의 깊이만으로 부스러질 수 있음 → 면적 한도와 실질적인 분할 보장.
- 배포 번들에 개발 getter의 삭제 구문만 남음 → 삭제도 DEV 조건 안으로 이동.
- 초기 모드 왕복 테스트는 누르기 전에 조각 수를 기준으로 잡아 실패했다.
  누르는 동안의 정상 파괴를 반영한 뒤 전환 직전 수·시드를 비교하도록 수정해 재검증했다.
  desktop-browser-first-run.json에는 그 초기 실패를 숨기지 않고 보관했다.
  desktop-mode-final.json이 수정된 검사 결과다.
- 일부 초기 JSON/이미지는 중간 구현 시점의 기록이다. 최종 결과는 final-* 파일과
  node-test-results.txt/lint-results.txt/build-results.txt를 우선 확인한다.
- 단일 정지 화면을 움직임의 증거로 취급하지 않았다. JSON의 time/contact/depth/center/
  displaced/raised/trail/waves/tip/x/y/vx/vy를 통해 시간 변화를 확인했다.

- iOS Safari/iPadOS, Android 실기기, macOS/Linux 브라우저의 실제 실행.
  iOS는 사용자가 실기기 검증을 제외하도록 수정한 범위에 맞춰 호환 경로만 구현했다.
- 실제 탭 숨김: 누른 채 새 탭을 만들었으나 도구가 원래 문서를 계속 visible로 유지했다. 따라서 hidden 전환과 복귀의 실제 조합은 미검증이다. tab-interruption-attempt.json에 이 시도를 보관했다.
- 실제 손가락/펜의 OS 터치 제스처 및 iOS 백그라운드 복귀 후 스피커 출력.
- 스피커·헤드폰별 주관적인 음색/음량 밸런스와 저사양 휴대폰의 GPU 프레임 시간.
- 네이티브 iOS 앱 프로젝트나 별도 OS 패키징은 이 웹 저장소에 없고 이번에 추가하지 않았다.
- 실제 3D 부피·응력·유체 정확도를 보장하지 않는다.

직접 재현할 순서
1. frontend에서 개발 서버를 실행하고 로그인 후 /mallang으로 이동한다.
2. 중앙을1초 이상 누른 뒤 천천히 좌우로 문지르고, S자·좁은 원·왕복을 시도한다.
3. 가장자리를 눌러 융기를 보고, 천천히 바깥으로 당긴다. 멈춘 포인터에 몸이 따라오는지 본다.
4. 놓았다가 이동 중 다시 잡아 반대로 당긴다. 벽까지 보내 반발과 함몰 복원을 함께 본다.
5. 왁뿌볼로 전환한다. 짧게 클릭한 뒤 길게 눌러 차이를 보고, 누른 채 이동한다.
6. 같은 조각을 다시 눌러 세분화한다. 모드 왕복으로 진행 유지, 복원 버튼으로 새 균열을 확인한다.
7. 창 크기를 바꾸고, 누르는 도중 다른 컨트롤/탭으로 이동해 입력이 남지 않는지 본다.
8. 볼륨0으로 바꾸고 새로고침 후 저장을 확인한 뒤 원하는 음량으로 복구한다.
9. 자동 재현: /tests/mallang-browser.html?inspect=1 에서 suite / wax / wax-drag / switch 실행.
   작은 모션 경로: 같은 주소에 &reduced=1. 이 페이지는 Vite 개발 전용이며 배포에서 제외된다.
10. 검증 명령(작업 디렉터리 frontend):
    node --test tests/*.test.js
    node node_modules/eslint/bin/eslint.js .
    node node_modules/vite/bin/vite.js build
    일반 npm 환경에서는 npm run lint / npm run build도 동일한 스크립트다.
    이 실행 환경에는 npm 명령이 없어 설치된 실행 파일을 Node로 직접 호출했다.
